Switch between Vercel accounts without logging out.

vcp gives each Vercel account its own login and picks the right one for the folder you are in. Deploy from any repo and it goes to the account that owns it.

curl -fsSL https://raw.githubusercontent.com/ArinPrajapati/vcp/main/install.sh | sh

Free and open source (MIT). macOS and Linux. Needs the Vercel CLI and git. Read the script first.

~/client-site $ vcp currentwork
work (from ~/client-site/.vercel-profile)
~/client-site $ vercel whoami
acme
~/side-project $ vcp currentpersonal
personal (from global)
~/side-project $ vercel whoami
sam

Same command, different folder, different account. No logout, no login.

The Vercel CLI keeps one login

The Vercel CLI stores a single login in a single folder. If you use more than one Vercel account, say a job and a side project, or one per client, you have two choices. Run vercel logout and vercel login every time you switch, or risk a deploy to the wrong account.

The mistake is easy to make and tedious to undo. A project is also linked to the account that created it, so a repo opened under the other login fails with "project not found".

vcp fixes this by giving every account its own login folder and choosing between them for you.

Set up in three steps

  1. Install

    Run the install command above, then open a new terminal. vcp doctor checks that everything is in place.

  2. Add your accounts

    Import the login you already have, then log in to each other account. Add as many as you need.

    vcp import personal   # adopt your current Vercel login
vcp add work          # opens the browser to log in

  3. Pin each repo to its account

    Run this once inside a repo. It writes a small .vercel-profile file, and every subfolder uses it.

    cd ~/client-site
vcp pin work
vercel deploy        # prints: vcp: profile work (...)

How vcp picks the account

The first match wins:

  1. VERCEL_PROFILE, to change one terminal only
  2. The nearest .vercel-profile file, searched upward from the current folder
  3. The global default you set with vcp use

Under the hood each profile is a folder in ~/.vercel-profiles/, and vcp runs the real Vercel CLI with its --global-config flag pointed at it. There is no background process and nothing to patch.

Commands

CommandWhat it does
vcp lsList profiles. A star marks the one in effect.
vcp currentShow which profile is active and why.
vcp whoamiAsk Vercel which user the active profile is.
vcp add <name>Create a profile and log in.
vcp import <name>Copy your existing Vercel login into a profile.
vcp pin [name]Pin the current folder tree to a profile.
vcp use <name>Set the global default profile.
vcp as <name> <args>Run one Vercel command as another profile.
vcp rm <name>Delete a profile and its login.
vcp doctorCheck PATH, profiles and logins.

Deploy-style commands print the active profile on stderr, so you always see where a deploy is going. Set VCP_QUIET=1 to silence it.

Who it is for

vcp helps when you are more than one Vercel user on one machine. It is not for one user in several teams, which the Vercel CLI already handles.

Job and side projects
Work has its own Vercel account and your side projects live on a personal one. Pin the work repos to the work profile and everything else stays personal.
Freelancers and consultants
Each client gave you a login. Make one profile per client and you are signed in as the right one as soon as you open their repo.
Open-source maintainers
Keep a personal account and a separate account that owns a project's site or docs.
Production separation
Company policy keeps production on its own account. A pinned repo can only deploy where its pin says.
Demos and streams
Use a clean demo account on screen with VERCEL_PROFILE=demo in that terminal only.
AI coding agents
Agents run vercel in many repos. Pins make each run use the right account instead of whichever login was last.

You do not need vcp if you have one Vercel account, if you only need to move between teams (use vercel switch or --scope), or in CI (use a token in VERCEL_TOKEN).

Questions

Can I use more than two Vercel accounts?

Yes. Every account is its own profile, and there is no limit on how many you add. Run vcp add with a new name for each one.

Does vcp work with Vercel teams?

vcp is for separate personal logins. If you are one user who belongs to several teams, use the Vercel CLI's own vercel switch command or the --scope flag. You can still use teams inside each profile.

Where are my logins stored, and is it safe?

Each profile is a folder in ~/.vercel-profiles with the same auth.json the Vercel CLI writes. The folders are private to your user (mode 700, files mode 600). vcp never prints or sends tokens, makes no network calls of its own, and has no telemetry.

Does it work in CI?

Yes. In CI, set VERCEL_TOKEN as usual. When vcp sees a token, a --token flag or --global-config, it steps aside and runs the Vercel CLI unchanged.

Does vcp replace the Vercel CLI?

No. The vercel and vc commands become thin shims that choose a profile, add the --global-config flag, and run the real Vercel CLI. Everything else behaves as before.

Does it run on Windows?

vcp runs on macOS and Linux with a POSIX shell. Windows is not supported directly, but it works inside WSL.

How do I uninstall it?

Run ~/.config/vcp/uninstall.sh. It removes the PATH lines vcp added and keeps your logins. Add --purge to delete the profiles too.
