How to switch Vercel accounts in the CLI

Short answer: vercel logout, then vercel login with the other account. That works, but you will repeat it all day. This guide covers what each command does and how to stop switching by hand.

Step by step: switch accounts with logout and login

vercel whoami     # see who you are right now
vercel logout     # remove the stored login
vercel login      # sign in as the other account
vercel whoami     # confirm

The CLI stores one login, so this replaces it. The old account is signed out, and you have to repeat the browser sign-in each time you switch back.

Accounts and teams are different

A Vercel account is a user you log in as. A team is a workspace one account can belong to. vercel switch and the --scope flag move between teams inside the account you are logged in as. They do not change the user.

vercel switch my-team          # change team scope
vercel deploy --scope my-team  # one command, another team

If your two "accounts" are really two teams under one login, you do not need anything else. If they are two separate users, with different emails, you need to switch the login itself.

Stop logging out: one profile per account

The CLI can read its login from any folder you point it at. vcp keeps one folder per account and chooses between them for you:

vcp import personal    # keep your current login
vcp add work           # log in the other account once
vcp ls                 # list profiles
vcp use work           # set the default
vcp pin personal       # or pin the current repo to one account
vcp as work whoami     # run one command as another account

After that, vercel and vc work as usual. To see which account a command will use, run vcp current. It shows the profile and where the choice came from.

If a deploy says "project not found" after switching

The folder's .vercel/project.json points to a project owned by the other account. Either switch back to the account that owns it, or relink the repo with vercel link under the account you want. With vcp, pin the repo to the owning profile so it always runs as the right user.
